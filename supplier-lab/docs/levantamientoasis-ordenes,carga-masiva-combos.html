Observaciones AS-IS

Hallazgos descriptivos del flujo actual, sin proponer solución.

Observado

El formato se descarga desde el detalle del producto

El dropshipper entra al producto, consulta el ID y descarga el formato desde una acción ubicada junto al botón de corazón.

Se intentan cargar dos combos

El archivo contiene una fila con el combo variable ID 2152017 y otra con el combo simple ID 2151821.

El sistema exige combo_combination_id

Después de procesar el archivo, el sistema devuelve errores indicando que debe informarse la combinación del combo para ambos productos.

La plantilla descargada no incluye combo_combination_id

En el formato descargado no se observa una columna para diligenciar el campo combo_combination_id, aunque el procesamiento lo exige.

Al agregar el identificador correcto el error cambia

Después de diligenciar los identificadores correctos visibles en el front, 133 y 102, el sistema responde que esas variaciones no pertenecen a los productos 2152017 y 2151821.

El flujo no permite continuar

Con los errores actuales no se logra crear la orden masiva para combo variable ni para combo simple.

El identificador correcto no es aceptado por la carga masiva

El dato usado corresponde al identificador que el front entrega para la combinación. Aun así, el procesamiento devuelve que la variación no pertenece al producto.

El error también ocurre para combo simple

El mensaje no solo aparece para el combo variable, sino también para combo simple 47 stock.

El archivo de errores agrega columnas adicionales

En el archivo de errores se observan columnas opcionales como transportadora, cédula y colonia, además de la columna ERROR.

Existe advertencia de duplicidad al recargar

El modal advierte que, si hubo errores, no debe volver a cargarse el mismo archivo seleccionado porque los pedidos serán repetidos.

El front sí muestra identificadores, pero la carga no los acepta

El comportamiento observado sugiere que tanto combo simple como combo variable requieren un identificador de combinación. Ese identificador sí se puede obtener desde el front, pero al cargarlo en órdenes masivas el sistema no lo reconoce como perteneciente al producto.

Insight clave: comportamiento del combo en órdenes masivas

Decisión abierta identificada a partir de los errores del flujo actual.

Insight

El problema principal es de funcionamiento en la carga masiva

El flujo actual muestra que el sistema exige una combinación del combo y que el front entrega un identificador para esa combinación. Sin embargo, al usar ese identificador en la plantilla, el procesamiento responde que la variación no pertenece al producto. El bloqueo ya no parece ser únicamente de comprensión del usuario, sino de validación o relación interna durante la carga masiva.

Modelo posible A · Todos los combos como combinaciones

El combo simple y el combo variable se comportan como productos que requieren identificar una combinación del combo. En ese caso, incluso el combo simple tendría una combinación única. En el AS-IS, los identificadores visibles se usan, pero el sistema los rechaza.

Modelo posible B · Simple como simple, variable como variable

El combo simple se cargaría solo con ID de producto, mientras que el combo variable requeriría identificador adicional de combinación. En el AS-IS, el sistema exige combinación para ambos casos, incluido el combo simple.

Lo más importante para el AS-IS

Independientemente del modelo correcto, el flujo actual no permite completar la carga masiva. El identificador que el front entrega para la combinación se usa en el archivo, pero el procesamiento responde que no pertenece al producto. Esto bloquea la creación de órdenes masivas para combos.

Criterio operativo mínimo

El usuario debe poder completar la carga masiva de combos con una plantilla entendible y funcional. Si el sistema exige una combinación y el front muestra su identificador, ese identificador debe ser aceptado por el procesamiento y permitir crear la orden.

Resumen AS-IS parcial actualizado

Síntesis del tramo documentado hasta ahora.

Parcial
El dropshipper entra al detalle de productos tipo combo.
Se revisa el combo variable Producto Variable 146 Stock con ID 2152017.
Se revisa el combo simple Combo Simple 47 Stock con ID 2151821.
Desde el detalle del producto existe una acción para descargar el formato de órdenes masivas.
El formato descargado solicita datos de cliente, dirección, ubicación, teléfono, ID de producto, cantidad, precio total, recaudo, nota y email opcional.
El archivo se diligencia con dos filas: una para el combo variable y otra para el combo simple.
El archivo se carga desde el modal de órdenes masivas en Mis Pedidos.
El sistema procesa el archivo y genera un archivo de errores.
El error indica que debe informarse combo_combination_id para el producto Producto Variable 146 stock.
El error también indica que debe informarse combo_combination_id para el producto combo simple 47 stock.
La plantilla descargada no muestra una columna combo_combination_id para diligenciar ese dato.
En un segundo intento se agrega ID DE VARIABLE con los identificadores correctos visibles en el front: 133 y 102.
El sistema devuelve que la variation 133 no pertenece al producto 2152017.
El sistema devuelve que la variation 102 no pertenece al producto 2151821.
Con este resultado el flujo queda bloqueado y no se puede continuar con la creación de órdenes masivas para estos combos.
Insight agregado: el identificador sí existe y sí es el que entrega el front, pero el procesamiento de carga masiva no lo reconoce correctamente.
Sigue abierta la definición técnica de si todos los combos deben comportarse como combinaciones o si el combo simple debe cargarse como producto simple y el variable como variable.
Independientemente de esa decisión técnica, el flujo de carga masiva debe funcionar de punta a punta usando los identificadores que la interfaz entrega al usuario.
