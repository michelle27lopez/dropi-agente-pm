# Research: Prueba de Integracion Exa E2E


## Síntesis (Exa Agent)

Para realizar pruebas de integración (E2E) con Exa, se recomienda estructurar un conjunto de pruebas utilizando herramientas como Vitest o Jest junto con el paquete exa-js [1][2]. La clave es utilizar variables de entorno para gestionar la API Key, saltando las pruebas si esta no está presente para evitar errores en entornos sin acceso a secretos [1][2].

El flujo de trabajo estándar en GitHub Actions incluye los siguientes pasos:

1. Configurar la API Key como un secreto del repositorio mediante el CLI de GitHub [1][3]:
```bash
gh secret set EXA_API_KEY --body "tu-api-key"
```

2. Definir una suite de pruebas de integración que verifique la conectividad y las funciones principales, tales como `search`, `searchAndContents` y `findSimilar` [1][2].

```typescript
// tests/exa.integration.test.ts
import { describe, it, expect } from "vitest";
import Exa from "exa-js";

const describeWithKey = process.env.EXA_API_KEY ? describe : describe.skip;

describeWithKey("Exa API Integration", () => {
  const exa = new Exa(process.env.EXA_API_KEY!);

  it("should search and return results", async () => {
    const result = await exa.search("JavaScript", { numResults: 1 });
    expect(result.results.length).toBeGreaterThanOrEqual(1);
  }, 10000);
});
```

Si experimentas problemas de tiempo de espera debido a la latencia de la API, se recomienda incrementar el tiempo de espera del test a 15000ms [1][4].
